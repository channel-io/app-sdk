# config.display.load 사용 가이드

`config.display.load`는 앱이 조회한 정보를 표준 설정 화면의 읽기 전용 필드에 표시하는 hook입니다.
앱은 표시할 값을 반환하고, 설정 화면은 기존 Config 필드에 그 값을 채웁니다.
Config의 필드 정의 방식은 그대로 사용합니다.

## 사용할 때

다음 조건을 모두 만족하는 정보를 설정 화면에 보여줄 때 사용합니다.

- 원본 데이터는 앱 DB나 외부 서비스에서 관리합니다.
- 사용자는 값을 확인하기만 하면 되고, 설정 화면에서 직접 수정할 필요가 없습니다.
- 값을 Config에 저장하거나 이후 함수 호출의 `ctx.config`로 전달할 필요가 없습니다.

| 필요한 동작                                    | 사용할 기능            |
| ---------------------------------------------- | ---------------------- |
| 앱에서 조회한 값을 읽기 전용으로 표시          | `config.display.load`  |
| 사용자가 입력한 값을 저장하고 앱에서 사용      | 일반 Config 필드       |
| 입력값이 바뀔 때 다른 입력값을 계산하거나 보정 | `config.draft.resolve` |
| 저장한 설정을 사용할 수 있는지 판단            | Config 검증            |

표시값은 현재 화면의 메모리에만 있습니다. 화면을 다시 열면 새로 조회하며, 표시값만 바뀌어도
저장 버튼이 활성화되지는 않습니다. 표시 전용 필드만 있으면 기본 저장 버튼을 만들지 않습니다.

## 사용하는 방법

### 1. 표시할 필드 지정

기존 `metadata.getConfigSchema` 응답의 `blocks`에 표시할 필드를 정의하고 다음 속성을 지정해주세요.

| 속성           | 설정                                   |
| -------------- | -------------------------------------- |
| `key`          | 함수가 반환할 표시값의 key와 같은 값   |
| `type`         | 표시할 값에 맞는 기존 Config 필드 타입 |
| `readOnly`     | `true`                                 |
| `storageClass` | `"transient"`                          |

`readOnly`는 사용자 편집을 막고, `transient`는 저장 대상에서 제외합니다. 두 조건을 모두 만족해야
표시값을 채울 수 있습니다. 기존 `readonly: true` 표기도 지원합니다.
password, credential, `sensitive: true`, `resolvesTo`가 있는 필드는 사용할 수 없습니다.

### 2. 값을 조회할 함수 연결

같은 스키마 응답의 `hooks` 배열에 다음 항목을 추가해주세요.
`<app-function-name>`을 앱에 등록한 실제 함수 이름으로 바꾸고, 기존 hook은 함께 유지합니다.

```json
{
  "type": "config.display.load",
  "actionFunctionName": "<app-function-name>"
}
```

`config.display.load`는 정해진 hook 이름입니다. `actionFunctionName`은 이 hook이 호출할 일반 앱
함수의 이름이며, 앱에서 정합니다. hook을 추가하면 표준 설정 화면이 이 함수를 호출하므로
별도의 WAM 호출 코드를 작성할 필요는 없습니다.

### 3. 앱 함수에서 조회값 반환

연결한 함수에서 인증된 호출 대상의 데이터를 조회하고 `{ displayValues: { [fieldKey]: value } }`를
반환해주세요. `fieldKey`는 1단계에서 정의한 필드의 `key`입니다. 새 필드를 만들거나 스키마를
반환하는 함수가 아니라, 이미 정의된 필드에 채울 값만 반환하는 함수입니다.

TypeScript SDK에서는 `@Func`로 일반 앱 함수를 등록하고, 같은 이름을 `actionFunctionName`에
지정해주세요. 함수 클래스는 NestJS의 `providers`에 등록합니다.
자세한 방법은 [함수 등록](../functions.md)을 참고해주세요.

입력과 응답 스키마는 다음과 같습니다. `z`는 `zod`에서 가져옵니다.
등록할 함수의 `@InputSchema`와 `@OutputSchema`에 각각 사용해주세요.

```ts
const DisplayLoadInputSchema = z
  .object({ key: z.string().optional() })
  .strict();
const DisplayLoadOutputSchema = z
  .object({ displayValues: z.record(z.string(), z.unknown()) })
  .strict();
```

응답의 최상위 속성은 `displayValues` 하나입니다. 필드별 타입은 설정 화면이 Config 정의를 기준으로
검증하므로, 출력 스키마에 모든 필드를 중복 정의할 필요는 없습니다.
함수에서는 데이터를 조회만 하며, 설정을 저장하거나 외부 데이터를 변경하지 않습니다.

## 함수에 전달되는 값

| 설정 방식               | `params`                          | 저장된 값의 위치           |
| ----------------------- | --------------------------------- | -------------------------- |
| 단일 설정               | `{}`                              | `ctx.config`               |
| 복수 설정의 저장된 항목 | `{ "key": "<saved-config-key>" }` | `ctx.config?.[params.key]` |
| 복수 설정의 새 항목     | 저장 전에는 호출하지 않음         | 없음                       |

단일 설정은 저장된 값이 없어도 호출합니다. 복수 설정은 `supportsMultiple: true`로 사용하며,
새 항목을 저장한 뒤 반환된 key로 호출합니다. 복수 설정의 `ctx.config`는 항목이 하나여도
key별 값의 맵입니다. 편집 중인 미저장 입력값은 표시 함수의 `params`에 전달하지 않습니다.

채널·매니저 스콥을 모두 지원합니다. 채널 ID는 인증된 `ctx.channel.id`에서 읽습니다.
매니저 스콥은 `ctx.caller.type === "manager"`인 `ctx.caller.id`의 본인 설정이며,
매니저 context가 없으면 함수에서 오류를 반환해야 합니다. `scope`, `channelId`, `managerId`를
`params`에 추가하지 않습니다. 복수 설정의 key로 데이터를 찾을 때도 해당 채널·매니저 소유인지 확인해주세요.

조회에 필요한 값이 아직 준비되지 않았다면 앱이 빈 상태를 처리합니다.
처음 연동하기 전처럼 표시할 정보가 없으면 `{ displayValues: {} }`를 반환할 수 있습니다.
플랫폼이 누락된 입력값을 만들어주지는 않습니다. 이전 표시값까지 지우려면 해당 key에 `null`을 반환해주세요.

## 응답 규칙

응답 key는 기존 `field.key`와 정확히 일치해야 합니다. 그룹 안의 필드도 동일합니다.
점이 포함된 key도 그대로 사용하며, 중첩 객체의 경로로 해석하지 않습니다.

| 필드 타입            | 반환할 값                                                                                                                                     |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`, `textarea`   | 문자열                                                                                                                                        |
| `number`             | 유한한 숫자                                                                                                                                   |
| `switch`, `checkbox` | boolean                                                                                                                                       |
| `select`, `radio`    | 현재 선택지의 `value` 또는 빈 문자열                                                                                                          |
| `multiselect`        | 현재 선택지의 `value`로 구성한 배열                                                                                                           |
| `phone`              | 문자열 `countryCode`, `number`를 가진 객체                                                                                                    |
| `address`            | 문자열 `name`, `zipcode`, `address1`, `address2`와 `phone` 구조의 `cellphone`을 가진 객체                                                     |
| `image`              | 문자열 `name`, `contentType`, 0 이상의 유한한 숫자 `size`, 문자열 `dataUrl`·`url`·`previewUrl` 중 하나를 가진 객체. `multiple: true`이면 배열 |

위 필드들은 모두 `null`로 비울 수 있습니다. 그 외 타입은 지원하지 않습니다.
동적 선택지는 초기 조회를 마친 뒤 표시값을 검증하며, 새 항목 저장 후에도 같은 key로 선택지를
조회한 다음 표시값을 검증합니다. 이전 선택값이 새 선택지에서 유효하지 않으면 비웁니다.

| 반환한 내용                                        | 화면 처리                                                  |
| -------------------------------------------------- | ---------------------------------------------------------- |
| key 생략 또는 빈 `displayValues`                   | 같은 대상의 이전 표시값 중 현재 필드 정의에 유효한 값 유지 |
| `null`                                             | 해당 필드 비우기. `defaultValue`를 다시 적용하지 않음      |
| `false`, `0`, `""`                                 | 필드 타입에 맞으면 그대로 적용                             |
| `{}` 또는 `displayValues: null`                    | 응답 형식 오류                                             |
| 미정의 key, 잘못된 타입, 저장 필드가 하나라도 포함 | 응답 전체 거부. 일부만 적용하지 않음                       |

`null`로 비운 스위치·체크박스는 `false`, 복수 선택은 `[]`가 됩니다.

## 호출 시점과 실패 처리

설정 화면 진입, 기존 설정 새로고침, 연동 완료 후 갱신, 표시값 조회 재시도 때 호출합니다.
입력값을 편집할 때마다 호출하지는 않습니다.

- hook이 없으면 호출을 생략하고 기존 Config 동작을 유지합니다.
- 등록한 함수가 없거나 조회·응답 검증에 실패하면 오류 배너와 재시도를 표시합니다.
- 같은 대상의 조회가 실패하면 마지막 성공값을 유지합니다.
- 표시값 재시도와 OAuth 연동 완료 후 갱신은 편집 중인 일반 설정값을 유지합니다.
- 대상 변경이나 화면 종료 후 도착한 응답은 적용하지 않습니다.

표시값은 저장 요청, `ctx.config`, 설정 검증과 연동 완료 판정에 포함하지 않습니다.
따라서 값이 보인다는 사실만으로 연동 성공을 판단해서는 안 됩니다.

## 적용 전 확인

이 hook을 지원하는 AppStore 서버와 표준 설정 화면이 필요합니다. SDK 업데이트만으로 활성화되지는
않으며, 이전 서버는 새 hook을 거부합니다.

2026-09-15 기준 SDK 0.24.2의 `GetConfigSchemaOutputSchema`에는 hook 배열과 `readOnly` 정의가 없습니다.
이 helper를 사용 중이라면 `metadata.getConfigSchema`의 출력 스키마를
`@OutputSchema(z.record(z.string(), z.unknown()))`으로 지정해 해당 속성을 보존해주세요.
AppStore의 Config 스키마 검증과 표시 응답 검증은 그대로 적용됩니다.

단일 설정의 저장된 연동 요약에는 `overviewSummary: true`인 필드의 표시값을 노출할 수 있습니다.
2026-09-15 기준 복수 설정은 상세 화면에서만 표시값을 확인할 수 있습니다.
목록 카드는 저장된 값만 사용하므로, 이 hook의 표시값은 노출하지 않습니다.
