# config.display.load 利用ガイド

`config.display.load` は、アプリが取得した情報を標準設定画面の読み取り専用フィールドに表示する hook です。
アプリが表示値を返すと、設定画面が既存の Config フィールドにその値を反映します。
Config フィールドの定義方法は変わりません。

## 使用する場面

次の条件をすべて満たす情報を設定画面に表示する場合に使います。

- 元のデータはアプリの DB または外部サービスで管理している。
- ユーザーは値を確認するだけで、設定画面で直接編集する必要がない。
- Config に保存したり、以降の Function 呼び出しで `ctx.config` に渡したりする必要がない。

| 必要な動作                             | 使用する機能             |
| -------------------------------------- | ------------------------ |
| アプリが取得した値を読み取り専用で表示 | `config.display.load`    |
| ユーザーの入力値を保存してアプリで使用 | 通常の Config フィールド |
| 入力値の変更時に別の入力値を計算・補正 | `config.draft.resolve`   |
| 保存済みの設定が使用可能かを判定       | Config 検証              |

表示値は現在の画面のメモリにだけ保持します。画面を開き直すと再取得します。
表示値だけが変わっても保存ボタンは有効になりません。
表示専用フィールドしかない場合、標準の保存ボタンは表示しません。

## 使用方法

### 1. 表示するフィールドを指定

既存の `metadata.getConfigSchema` レスポンスの `blocks` にフィールドを定義し、次のプロパティを指定してください。

| プロパティ     | 設定                                        |
| -------------- | ------------------------------------------- |
| `key`          | Function が表示値を返す際に使うキーと同じ値 |
| `type`         | 表示値に合う既存の Config フィールド型      |
| `readOnly`     | `true`                                      |
| `storageClass` | `"transient"`                               |

`readOnly` はユーザーによる編集を禁止し、`transient` は保存対象から除外します。
表示値を反映するには両方が必要です。従来の `readonly: true` 表記にも対応しています。
password、credential、`sensitive: true`、`resolvesTo` があるフィールドは使用できません。

### 2. 値を取得する Function を接続

同じスキーマレスポンスの `hooks` 配列に次の項目を追加してください。
`<app-function-name>` を登録済みのアプリ Function 名に置き換え、既存の hook は配列内に残します。

```json
{
  "type": "config.display.load",
  "actionFunctionName": "<app-function-name>"
}
```

`config.display.load` は決められた hook 名です。`actionFunctionName` はこの hook が呼び出す
通常のアプリ Function 名で、アプリ側で決めます。hook を追加すると標準設定画面が呼び出すため、
WAM 側に別の呼び出しコードを書く必要はありません。

### 3. アプリの Function で値を取得して返す

接続した Function で、認証済みの呼び出し元のスコープに属するデータを取得し、
`{ displayValues: { [fieldKey]: value } }` を返してください。`fieldKey` は手順1で定義したフィールドの
`key` です。フィールドを新しく作成したりスキーマを返したりせず、既存フィールドに表示する値だけを返します。

TypeScript SDK では `@Func` で通常のアプリ Function を登録し、同じ名前を
`actionFunctionName` に指定してください。Function のクラスは NestJS の `providers` に登録します。
詳しくは [Function 登録](../functions.md) を確認してください。

入力と出力のスキーマは次のとおりです。`z` は `zod` から import します。
Function の `@InputSchema` と `@OutputSchema` にそれぞれ指定してください。

```ts
const DisplayLoadInputSchema = z
  .object({ key: z.string().optional() })
  .strict();
const DisplayLoadOutputSchema = z
  .object({ displayValues: z.record(z.string(), z.unknown()) })
  .strict();
```

レスポンスの最上位プロパティは `displayValues` のみです。
設定画面が Config 定義に基づいてフィールドごとに値の型を検証するため、出力スキーマに全フィールドを
重複して定義する必要はありません。Function はデータの取得だけを行い、設定の保存や外部データの変更は行いません。

## Function に渡される値

| 設定方式               | `params`                          | 保存済みの値の参照先       |
| ---------------------- | --------------------------------- | -------------------------- |
| 単一設定               | `{}`                              | `ctx.config`               |
| 複数設定の保存済み項目 | `{ "key": "<saved-config-key>" }` | `ctx.config?.[params.key]` |
| 複数設定の新規項目     | 保存前は呼び出さない              | なし                       |

単一設定は保存済みの値がなくても呼び出します。複数設定は `supportsMultiple: true` で利用し、
新規項目を保存した後、返されたキーで呼び出します。複数設定の `ctx.config` は項目が1つでも
キーと値のマップです。編集中の未保存入力値は、表示用 Function の `params` に渡しません。

チャネルとマネージャーの両スコープに対応しています。チャネル ID は認証済みの `ctx.channel.id` から取得します。
マネージャースコープは、`ctx.caller.type === "manager"` のときの `ctx.caller.id` が示す本人の設定です。
マネージャーの context がない場合、Function でエラーを返す必要があります。
`scope`、`channelId`、`managerId` は `params` に追加しません。
複数設定のキーでデータを参照する場合も、対象のチャネルとマネージャーに属するかを確認してください。

取得に必要な値がまだ揃っていない場合は、アプリ側で空の状態を処理します。
初回連携前など、表示する情報がなければ `{ displayValues: {} }` を返せます。
プラットフォームが不足する入力値を自動で補うことはありません。
以前の表示値も消す場合は、そのキーに `null` を返してください。

## レスポンスのルール

レスポンスのキーは既存の `field.key` と完全に一致させます。グループ内のフィールドも同じです。
ドットを含むキーもそのまま使い、入れ子のオブジェクトへのパスとしては扱いません。

| フィールド型         | 返す値                                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`, `textarea`   | 文字列                                                                                                                                                        |
| `number`             | 有限の数値                                                                                                                                                    |
| `switch`, `checkbox` | boolean                                                                                                                                                       |
| `select`, `radio`    | 現在の選択肢の `value` または空文字列                                                                                                                         |
| `multiselect`        | 現在の選択肢の `value` で構成する配列                                                                                                                         |
| `phone`              | 文字列の `countryCode` と `number` を持つオブジェクト                                                                                                         |
| `address`            | 文字列の `name`、`zipcode`、`address1`、`address2` と、`phone` 構造の `cellphone` を持つオブジェクト                                                          |
| `image`              | 文字列の `name`、`contentType`、0以上の有限の数値 `size`、文字列の `dataUrl`・`url`・`previewUrl` のいずれかを持つオブジェクト。`multiple: true` の場合は配列 |

上記のフィールドはすべて `null` で空にできます。それ以外の型には対応していません。
動的な選択肢は、初回取得を終えてから表示値を検証します。新規項目の保存後も、同じキーで選択肢を
取得してから表示値を検証します。以前の選択値が新しい選択肢で無効になった場合は空にします。

| 返す内容                                            | 画面の処理                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------ |
| キーの省略、または空の `displayValues`              | 同じ対象の以前の表示値のうち、現在のフィールド定義で有効な値を維持 |
| `null`                                              | フィールドを空にする。`defaultValue` は再適用しない                |
| `false`, `0`, `""`                                  | フィールド型に合う場合はそのまま適用                               |
| `{}` または `displayValues: null`                   | レスポンス形式のエラー                                             |
| 未定義のキー、不正な型、保存フィールドを1つでも含む | レスポンス全体を拒否。一部だけの適用はしない                       |

`null` で空にしたスイッチとチェックボックスは `false`、複数選択は `[]` になります。

## 呼び出しのタイミングとエラー処理

設定画面を開いたとき、既存設定の再読み込み時、連携完了後の更新時、表示値の取得を再試行するときに
呼び出します。入力値を編集するたびには呼び出しません。

- hook がなければ呼び出しを省略し、既存の Config の動作を維持します。
- 登録した Function がない場合や、取得・レスポンス検証に失敗した場合は、エラーバナーと再試行の操作を表示します。
- 同じ対象の取得に失敗した場合は、最後に取得できた値を維持します。
- 表示値の再試行と OAuth 連携完了後の更新では、編集中の通常の設定値を維持します。
- 対象の変更後や画面を閉じた後に届いたレスポンスは適用しません。

表示値は、保存リクエスト、`ctx.config`、設定検証、連携完了の判定には含めません。
そのため、値が表示されたことだけで連携成功を判断しないでください。

## 適用前の確認

この hook に対応した AppStore サーバーと標準設定画面が必要です。SDK の更新だけでは有効にならず、
以前のサーバーは新しい hook を受け付けません。

2026年9月15日時点では、SDK 0.24.2 の `GetConfigSchemaOutputSchema` に hook 配列と `readOnly` の定義がありません。
この helper を使っている場合は、`metadata.getConfigSchema` の出力スキーマを
`@OutputSchema(z.record(z.string(), z.unknown()))` にして、これらのプロパティを保持してください。
AppStore による Config スキーマ検証と表示レスポンスの検証は引き続き適用されます。

単一設定の保存済み連携サマリーには、`overviewSummary: true` のフィールドの表示値を表示できます。
2026年9月15日時点では、複数設定の表示値は詳細画面でのみ確認できます。
一覧カードは保存済みの値だけを使うため、この hook の表示値は表示しません。
